## Product evaluation & architectural fit

obs-unified is built around a specific architecture: **a self-hosted telemetry graph that unites distributed traces, structured logs, session replay (rrweb), and AI agent observability under one identity chain**.

Rather than publishing unverified third-party feature checklists or pricing claims, this guide provides a concrete framework outlining repo-backed obs-unified capabilities and operational boundaries.

### Correlated telemetry graph architecture

obs-unified structures telemetry as an interconnected graph rather than isolated signal stores:

- **Unified identity chain**: OpenTelemetry spans, structured logs, browser session replays, and AI agent spans share common execution identifiers (`trace_id`, `span_id`, `session_id`, `interaction_id`).
- **Full-stack traversal**: Client interaction events recorded in browser sessions correlate directly with backend distributed trace spans, structured application logs, and downstream LLM agent tool calls.
- **AI & agent observability**: Agent action tracking captures LLM prompts, token usage, latency, and tool execution steps as first-class graph nodes.

### Supported storage engines & deployment models

obs-unified supports two self-hosted deployment targets implemented in the repository:

1. **Cloudflare Serverless**:
   - Collector and dashboard run on Cloudflare Workers.
   - Relational metadata and traces persist in Cloudflare D1.
   - Session replay chunks and large payloads persist in Cloudflare R2 object storage.
2. **Node Service**:
   - Collector and web server run as a Node.js process.
   - Relational metadata and telemetry persist in PostgreSQL.
   - Session replay payloads store in S3-compatible object storage.
   - Automated retention sweeps and cleanup tasks run via maintenance scripts.

Telemetry is written directly to the datastores provisioned in your deployment.

### Documented limitations & trade-offs

We believe candid self-assessment is essential. If any of the following are immediate requirements, other specialized tools may better suit your needs:

- **Maturity**: obs-unified is early-stage software optimized for single-team deployments rather than complex enterprise organizations.
- **Authentication & access control**: Uses single-password or bearer token authentication. Enterprise SSO, SAML, and fine-grained role-based access control (RBAC) are not implemented.
- **Protocols**: Telemetry ingestion is currently OTLP/HTTP-only. Direct OTLP/gRPC ingestion is not supported natively; gRPC exporters should be fronted with a standard OpenTelemetry Collector.
- **Query & dashboarding**: Analyses emphasize AI-assisted investigation, root cause narratives, and trace traversal rather than arbitrary custom dashboard query builders (such as PromQL, NRQL, or SQL panel editors).
- **Storage capacity & retention**: D1 storage is subject to database size limits and retention policies; high-throughput workloads requiring long-term data retention should deploy the PostgreSQL adapter with automated retention pruning.
