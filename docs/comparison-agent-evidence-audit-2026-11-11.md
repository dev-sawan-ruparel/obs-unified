## 1. Rows and verdict rules

Vendor-documented AI-assistant, agent, preview, beta, and early-access capabilities count; the stage is named in the cell. `no` is used only where the cited page says so; none of these cells needed it. Main-table cells are short descriptions of the same evidence: `TRUE` means the description matches the cited page, and `UNVERIFIABLE` marks an inferential negative rendered as *Not marketed†*.

| Row | Question | Yes | Partial |
|---|---|---|---|
| `compact_evidence_bundles` (Compacted evidence for AI agents) | Can an AI agent get compacted telemetry evidence (repeated records summarized, key records kept) sized for its context, with a way to fetch the full records? | Agent-facing output that compacts telemetry to fit an agent's context (budget, summaries, exemplars, pattern-collapsed logs) and a way to fetch the underlying records | Agent-facing truncation, pagination, or aggregation without stated compaction; compaction without a way to expand; or log patterns for people only |
| `agent_skills` (Agent skills for coding agents) | Does the vendor publish first-party agent skills that teach AI coding agents to instrument or investigate with the product? | First-party skills or a coding-agent plugin that ships skills, covering instrumentation or investigation | Rules or prompt files, an AI setup wizard, llms.txt, or MCP-served guides, but no installable skills |
| `one_id_chain` (One ID chain from user to agent action) | Do user, session, backend trace, and AI agent or LLM records share linking IDs, so you can go from a user to the backend work and agent actions their request caused? | Documented links from user or session to backend traces, and from LLM or agent traces to the app trace or to the user or session | Some of those links, not the whole chain |
| `instrumentation_gaps` (Points out gaps in your instrumentation) | Does the product detect and show where instrumentation is missing, such as uninstrumented time inside a trace? | Automated detection shown to users or agents: unaccounted span time, untraced services, or orphan spans from broken propagation | Setup or data-quality checks, or AI assistants that suggest instrumentation without detecting gaps |

## 5. Researcher notes

- **datadog · compact_evidence_bundles:** The MCP 'Context efficiency' section covers token-aware truncation with a way to request more, but no compaction of repeated records (no pattern-collapsed logs or exemplars) for agents. Code Execution (GA) lets the agent write its own reduction code, which is agent-side aggregation rather than product compaction. The tools page also says large traces 'may be truncated (and indicated as such) without a way to retrieve all spans.'
- **datadog · agent_skills:** DataDog/pup (main DataDog org) ships installable skills for Claude, Cursor, Codex and others. datadog-labs/agent-skills covers investigation (dd-logs, dd-apm) and instrumentation (dd-instrument-rum, dd-instrument-llmo). The datadog-labs org describes itself as 'experimental ... not supported by Datadog', and datadog-labs/claude-code-plugin is marked 'currently in Preview'. DataDog/datadog-api-claude-plugin is archived. The docs Skills Library is for skills users write themselves, not first-party skills.
- **datadog · one_id_chain:** All links are documented: RUM session to backend APM traces, LLM/agent spans to RUM sessions through the RUM session ID, and LLM/agent spans to APM spans ('select an Agent Observability span in the Agent Observability Explorer and click APM span to navigate to the relevant APM span', on the agent_observability_and_apm page, which llm_observability/monitoring/llm_observability_and_apm/ now redirects to). The RUM-to-LLM link requires forwarding the session ID by hand.
- **datadog · instrumentation_gaps:** I found no documented markers for uninstrumented span time or orphan spans in Trace View or the APM troubleshooting docs. Tag rules are a missing-attribute data-quality check, so this is partial. Inferred services find uninstrumented dependencies from client spans ('even if that dependency hasn't been directly instrumented') but present them as services, not as gaps. The MCP get_monitor_coverage tool finds monitor gaps, not instrumentation gaps.
- **sentry · compact_evidence_bundles:** Borderline. The agent-facing get_trace_details tool picks up to 96 'interesting' spans (errors, slow spans), reports 'Overview shows N of M spans', and points to search_traces or spanId to expand. The AI conversation spec truncates large GenAI payloads and lists truncatedFields with span and trace IDs for fetching the full values. Neither public docs nor these sources say the condensing is sized for an agent's context window (the code comments say 'display limits'), so this is partial. The evidence is in the vendor's GitHub source (commit d9238ee), not docs.sentry.io.
- **sentry · agent_skills:** getsentry/sentry-for-ai is the skill source. It builds getsentry/agent-plugin, a portable Agent Plugin that bundles 'The full, hydrated Sentry skill library as standard Agent Skills', along with client plugins for Claude Code, Cursor, Codex, Copilot, Grok and Antigravity. The skills include sentry-instrument, sentry-get-started and sentry-debug-issue, so they cover both instrumentation and investigation.
- **sentry · one_id_chain:** The full chain is documented. Session Replay connects to its traces, and distributed tracing runs from frontend to backend. Agent and LLM spans sit inside the same distributed trace, and the Conversations page shows the user who started each conversation: 'Each conversation in the list shows the user who initiated it alongside the project and conversation ID.' This requires setUser.
- **sentry · instrumentation_gaps:** The trace view detects broken subtraces and orphan transactions automatically and shows them with dashed lines. The changelog (Oct 29, 2024) confirms that unaccounted time between spans appears as 'missing instrumentation' spans, which users can toggle off. The .NET EF troubleshooting page mentions the same label.
- **posthog · compact_evidence_bundles:** Every part of the yes rule is met. This is an agent-facing MCP tool (logs-patterns, logs-patterns-diff) that compacts logs explicitly to save context, with a stated size budget of 200 templates. Each template keeps example lines and gives the agent a pivot to the raw records through query-logs with match_patterns, match_regex or match_literal. The MCP tool prompt describes the pivot step by step.
- **posthog · agent_skills:** PostHog/ai-plugin is described as the 'Official PostHog plugin for Claude Code, Cursor, Gemini, Codex and other AI coding tools'. Its skills directory includes instrument-* skills (instrument-tracing, instrument-logs, instrument-llm-analytics) and investigation skills (investigating-logs, exploring-apm-traces). The README says '30+', but the repo currently holds many more skill folders. PostHog/skills is also present and labeled 'under construction'.
- **posthog · one_id_chain:** The whole chain is documented. Backend spans carry the person (distinct ID) and session ID. LLM events link to application spans through $ai_trace_id. The link-session-replay page links LLM events to replays through $session_id and posthogDistinctId. Distributed tracing is in beta ('Note: Distributed tracing is in beta.'), and with PostHog SDKs the trace ID has to be set by hand. Joins across the two products are done in SQL, with an ID encoding conversion.
- **posthog · instrumentation_gaps:** Borderline. The MCP trace tool computes uncovered self-time for each span, and the first-party skill tells the agent to read a large value as an 'uninstrumented gap'. The detection still depends on the agent following that instruction, and I found no product marker for missing instrumentation, so this is partial. Ingestion warnings and SDK health issues are data-quality checks. The 'observability gaps' scout looks for events without dashboards or alerts, not for missing instrumentation.
- **honeycomb · compact_evidence_bundles:** Agent-facing aggregation/summaries (get_span_details, run_query, run_bubbleup) plus drill-down tools (get_trace, get_query_results) exist, but no doc states compaction sized to an agent's context; no log-pattern feature found in llms-full.txt.
- **honeycomb · agent_skills:** First-party repo github.com/honeycombio/agent-skill; skills cover otel-instrumentation and production-investigation, installable via claude plugin marketplace.
- **honeycomb · one_id_chain:** BORDERLINE yes/partial. Browser->backend trace propagation is documented (with user.id resource attributes), and agent/LLM work is OTel GenAI spans in your traces shown with related spans in Agent Timeline; docs do not show one explicit end-to-end example tying a user session to an agent conversation.
- **honeycomb · instrumentation_gaps:** Automatic missing-span warning in the trace view (broken traces; troubleshooting page also describes '(missing span)' gaps) plus a built-in Canvas skill that flags AI-agent instrumentation gaps. No 'uninstrumented time' marker found.
- **newrelic · compact_evidence_bundles:** Agent-facing pattern analysis and aggregate tools (get_log_statistics, get_error_statistics) plus raw-record tools exist, but no doc says the output is compacted to fit an agent's context or how a summary links to its underlying records.
- **newrelic · agent_skills:** First-party repos newrelic/claude-code-plugin (apm, finops, kubernetes, newrelic-mcp skills) and newrelic/nr-skills-hub (SKILL.md bundles for Claude Code, Cursor, Codex). Skills cover investigation, not instrumentation.
- **newrelic · one_id_chain:** End-user browser activity is linked to backend traces via distributed tracing, and APM agents record LLM calls in the application trace (AI response trace view); feedback events correlate by trace ID. Browser DT requires Browser Pro.
- **newrelic · instrumentation_gaps:** Trace UI shows an orphaned-span indicator for fragmented traces (broken propagation). The MCP gap tool is repo/config-level only (Python APM, browser snippet, change tracking).
- **grafana · compact_evidence_bundles:** Agent-facing pattern-collapsed logs (query_loki_patterns) plus query_loki_logs with a line limit and resultsTruncated flag; the README's explicit context-window management covers dashboard tools only, not telemetry, and patterns are not linked to their underlying lines.
- **grafana · agent_skills:** First-party repo with Claude Code plugin marketplace; skills include opentelemetry/beyla instrumentation, send-data, and frontend-session-rca investigation.
- **grafana · one_id_chain:** Session -> backend trace navigation (and trace -> session back-link) is documented; AI Observability (OpenLIT/OTel) traces run from user request through LLM calls, and Agent Observability conversation results include trace IDs (mcp-grafana README).
- **grafana · instrumentation_gaps:** Untraced services are inferred from spans and shown in a dedicated view (Tempo service-graph virtual nodes for uninstrumented client/server); an Instrumentation Quality report also flags missing attributes. No in-trace 'uninstrumented time' marker found.
- **signoz · compact_evidence_bundles:** Agent-facing aggregation, selectFields and paginated rows with completeness notes, but no stated compaction to an agent context budget. No log-pattern clustering found in the docs sitemap, llms.txt or changelog (only alert 'evaluation patterns').
- **signoz · agent_skills:** First-party SigNoz/agent-skills repo installable via plugin marketplaces and skills.sh; skills cover docs/instrumentation guidance, querying and alert investigation.
- **signoz · one_id_chain:** Frontend-to-backend trace linking and LLM spans inside the application trace are documented, but no user or session ID (RUM session) linking to backend traces was found; gen_ai.conversation.id covers LLM conversations only.
- **signoz · instrumentation_gaps:** Automated missing-span flag for unresolved parents (unexported services, dropped spans) in traces. Uninstrumented time between spans is only described as a visible gap, not flagged; the missing-span flag also fires for sampling/network loss, so this is borderline yes.
- **uptrace · compact_evidence_bundles:** list_log_groups/list_span_groups give agent-facing aggregation (log grouping is fingerprint-based), with list_logs/get_trace for records, but no stated compaction or size budget for agent context.
- **uptrace · agent_skills:** uptrace://skills/create-dashboard and uptrace://skills/create-monitor are MCP resources, not installable SKILL.md bundles or plugins; no skills/plugin repo found in the uptrace GitHub org (only uptrace/mcp).
- **uptrace · one_id_chain:** LLM spans linked to the application trace and a user ID attribute are documented; no user/session-to-backend-trace linking (browser session or RUM) documented — the browser guide covers fetch instrumentation without stating backend linking.
- **uptrace · instrumentation_gaps:** Only a manual 'Troubleshooting broken traces' guide (curl for traceparent) and a note that missing attributes cause missing service-graph nodes; no automated detection.
