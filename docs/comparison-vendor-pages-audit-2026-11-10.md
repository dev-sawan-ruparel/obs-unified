# Vendor comparison pages audit ledger (2026-11-10)

> Cells: **54** (9 vendors × 6 rows) for the per-vendor pages at `obsunified.com/compare/<vendor>/`. Verdicts: `yes` **26** · `partial` **17** · `no` **1** · `not_marketed` **5** · `not_stated` **5**.
>
> **Method:** three research passes, one per group of three vendors, fetched each vendor's own pages with `curl` (no page-fetch tool was needed) and quoted excerpts verbatim. A separate script then re-fetched every cited page and confirmed every excerpt appears on it (whitespace-insensitive): **90 of 90 excerpts found**. Search results were used only to find pages, never as evidence.
>
> **Scope:** these six rows were added for the per-vendor pages. The other rows on those pages reuse cells from [`comparison-full-audit-2026-10-13.md`](./comparison-full-audit-2026-10-13.md) and [`comparison-agent-access-audit-2026-11-10.md`](./comparison-agent-access-audit-2026-11-10.md).

## Rows and verdict rules

| Row | Question | Yes | Partial | No / Not marketed / Not stated |
|---|---|---|---|---|
| `mcp_read_only_default` | Is the vendor's MCP server read-only until write tools are turned on? | Docs say read-only by default, writes need an explicit opt-in (flag, toolset, scope), or there are no write tools | Write tools available by default, gated by the user's existing permissions, scopes, or key | `no` only if docs say writes are on with no gating; `not_stated` if the docs don't say |
| `mcp_links_to_records` | Do MCP tool results link back to the underlying records? | Docs say results carry links, URLs, or citations to records | Some tools, or a link-building tool | `not_stated` if the docs don't say |
| `agent_calls_in_app_traces` | Do AI agent runs and tool calls appear alongside the app's backend traces? | Docs say agent/LLM spans are linked with the app's traces | Separate view, manual correlation, or instrumentation guides without a product feature | `not_marketed` if none found |
| `profile_from_trace` | Can you open the CPU profile for a specific trace or span? | Docs describe span or trace to profile linking | Profiling without per-span linking, or language-limited preview | `no` only if the vendor says so; else `not_marketed` |
| `full_self_host` | Can you run the core platform on your own infrastructure, supported for production? | Documented self-managed deployment of the core platform; cloud-only add-ons noted | Documented limits: one signal, low-volume or unsupported, or paid features cloud-only | `not_marketed` if none found |
| `sso` | Is SAML or OIDC single sign-on built in? | Available on at least one paid plan or supported edition (plan named) | — | `not_marketed` if none found |

`no` is used only where the cited page says so. `not_marketed` and `not_stated` are never rendered as "No".
