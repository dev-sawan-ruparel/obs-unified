## Rows and verdict rules

Vendor-documented AI-assistant, agent, preview, beta, and early-access capabilities count; the stage is named in the cell. `no` is used only where the cited page says so; none of these cells needed it.

| Row | Yes | Partial |
|---|---|---|
| `tool_side_effects` (Records what an agent's tool call changed) | Before/after state, a diff, or an explicit mutation record for agent tool calls | Tool-call inputs and outputs only |
| `mcp_call_audit` (MCP calls recorded with trace context) | MCP-specific capture of the customer's MCP client or server calls (feature or vendor-documented instrumentation) linked to traces or agent runs | Generic tool-call spans, or audit logs covering only the vendor's own MCP server |

## Researcher notes

- **datadog · tool_side_effects:** Span attributes include inputs and outputs, and MCP call_tool spans carry parameters and response; no documented before/after state, diff, or side-effect record for tool calls.
- **datadog · mcp_call_audit:** Agent Observability (formerly LLM Observability) auto-instruments MCP clients (Python, JS SDK) and servers (Python), with MCP spans linked to the parent LLM span/trace.
- **datadog · prod_to_eval:** Datasets accept production traces (manual or via Automations) and Offline Experiments run against datasets and compare results across prompt/model changes; both (a) and (b) documented.
- **datadog · incident_memory:** Bits Investigation (Bits AI SRE) stores feedback from past investigations as memories and automatically selects them for similar future investigations. Memories come from user feedback on prior investigations.
- **datadog · query_language:** DDSQL is a documented SQL dialect over Datadog data including logs, metrics, and spans; Datadog also has log/trace query syntax not cited here.
- **sentry · tool_side_effects:** Agent tracing captures tool-call inputs and outputs; no documented before/after state, diff, or side-effect record.
- **sentry · mcp_call_audit:** MCP Servers monitoring (JS and Python SDKs) creates MCP spans within Sentry traces covering tools, resources, and prompts; it is server-side instrumentation of the customer MCP server.
- **sentry · prod_to_eval:** Sentry displays evaluator (LLM-as-judge) results recorded on production conversations, but no documented way to save traces into a dataset or compare versions on saved cases (no eval/dataset pages in the docs sitemap). The evaluators are run by the customer and only displayed by Sentry; not_marketed is a defensible alternative.
- **sentry · incident_memory:** Regression flags and AI-assisted grouping/Similar Issues exist, but Seer docs do not describe recalling similar past issues or investigations during root cause analysis.
- **sentry · query_language:** Explore offers a free-form query builder with search syntax, aggregate functions, and group-by over spans; not a standalone query language like SQL.
- **posthog · tool_side_effects:** Spans carry $ai_input_state and $ai_output_state (span input and output payloads); the Tools tab extracts tool names. No documented before/after mutation or diff record for tool calls.
- **posthog · mcp_call_audit:** MCP Analytics SDKs instrument the customer MCP server and group $mcp_tool_call events into sessions/conversations (agent runs); start-here page says MCP Analytics is in beta. Linkage is to MCP sessions/conversation IDs rather than AI Observability trace IDs.
- **posthog · prod_to_eval:** Datasets (beta) take items from production traces, and offline evals record experiments that can use a PostHog dataset and compare runs across prompt/model/code changes.
- **posthog · incident_memory:** Self-driving scouts (PostHog investigation agents) recall what earlier runs surfaced and cluster related signals into one report; error tracking separately auto-reopens resolved issues. Recall is of the scout's own prior findings, not an explicit "similar incidents" list, so partial is a defensible alternative.
- **posthog · query_language:** PostHog SQL (HogQL) is a documented SQL dialect over PostHog events; AI observability and MCP data are stored as standard events.
- **honeycomb · tool_side_effects:** Tool-call spans show arguments and results; no before/after state, diff, or side-effect record documented.
- **honeycomb · mcp_call_audit:** Generic execute_tool spans only; Honeycomb's MCP docs cover its own MCP server for agents to query Honeycomb, not monitoring of customer MCP clients/servers.
- **honeycomb · prod_to_eval:** No native Honeycomb dataset/eval-case store found; version comparison is over production telemetry, and dataset/eval runs happen in Braintrust through the Canvas connector. The blog also suggests asking Canvas to pull conversations for an eval dataset, but no product flow comparing versions on saved cases.
- **honeycomb · incident_memory:** Team Agents (early access per the Nov 3 2026 press release; GA announced for Dec 1) carry memories of past incidents into new investigations. Docs also say auto-investigations review earlier occurrences of the same alert; Canvas Memory (beta) is per-person facts.
- **honeycomb · query_language:** Free-form query builder with aggregations and group-by.
- **newrelic · tool_side_effects:** Inputs/outputs of tool calls captured; no before/after or mutation record documented.
- **newrelic · mcp_call_audit:** Node.js compatibility table lists Prompt Retrieval, Resource Reading and Tool Calls for @modelcontextprotocol/sdk; Python (MCP SDK, FastMCP) and Java (MCP Java SDK) also listed as AI monitoring libraries, captured in APM traces. The first quote introduces a table, so the supported operations are table cells rather than a sentence.
- **newrelic · prod_to_eval:** Only a version comparison over production traffic (b-like); no saving traces as dataset/eval cases found. Weak partial: comparison is performance/cost, not a scored eval; not_marketed is defensible.
- **newrelic · incident_memory:** Automatic memory extraction plus similarity retrieval of past lessons; opt-in, disabled by default, requires Advanced CCU SKU. No preview label found.
- **newrelic · query_language:** Query language with aggregation and FACET.
- **grafana · tool_side_effects:** Arguments/results and execution status captured; workflow steps record execution state but no before/after or diff of what a tool changed.
- **grafana · mcp_call_audit:** MCP-specific instrumentation of customer MCP clients and servers via OpenLIT SDK (OTel traces), in Grafana Cloud's 'OpenLIT Observability' section. The newer Agent Observability product docs don't mention MCP specifically.
- **grafana · prod_to_eval:** Both (a) promoting production conversations into versioned test suites and (b) side-by-side experiment comparison by agent version/model/prompt documented. No preview label on experiments (OTel ingestion is public preview).
- **grafana · incident_memory:** Private-preview IRM integration extracts hypotheses/actions/outcomes from past investigations onto the Knowledge Graph, which agents use as runtime context; matching is by affected system part, not documented as a similarity search, and it is blog-only (no docs page found). GA docs only offer incident history the Assistant can summarize on request, which would be partial.
